## 一、数据质量规范

### 1.1 行情数据规范

| 字段 | 数据源 | 格式 | 校验规则 | 异常处理 |
|:-----|:-------|:-----|:---------|:---------|
| 代码 | 腾讯行情 | 6位数字字符串 | 正则 `^\d{6}$` | 不合规→跳过并告警 |
| 名称 | 腾讯行情 | 中文字符串 | 含至少一个中文字符 | 不合规→跳过并告警 |
| 现价 | 腾讯行情 | 正浮点数 | `>0` | 异常→多源轮询补数 |
| 昨收 | 腾讯行情 | 正浮点数 | `>0` | 异常→标记为缺失 |
| 涨跌幅 | 腾讯行情 | 浮点数 | `交叉验证(现价-昨收)/昨收` | 偏差>0.1%→以计算值为准 |
| 换手率 | 腾讯行情 | 百分比 | `>=0 且 <=100` | 越界→标记异常 |
| 市盈率 | 腾讯行情 | 浮点数 | `-5000~5000` | 异常→标记为N/A |
| 复权类型 | 常量 | 字符串 | `"qfq"` | 缺失→补充默认值 |
| 更新时间 | 系统时间 | `YYYY-MM-DD HH:MM` | 盘中>15min过期 | 过期→告警 |

### 1.2 池数据规范

| 池 | 必填字段 | 容量 | 过期规则 | 校验规则 |
|:---|:---------|:----:|:---------|:---------|
| 快筛候选池 | 代码、名称、纳入日期、综合分 | 20 | 14天淘汰 | 同池代码唯一 |
| 重点观察池 | 代码、名称、纳入日期、综合分 | 20 | 评分衰减>15分 | 同池代码唯一 |
| S级操作池 | 代码、名称、纳入日期、综合评分、复权类型 | 3 | T+1过期(`>=`比较) | 今日条目优先保留 |
| 边缘池 | 代码、名称、综合分、降级时间 | 30 | 30天淘汰 | 降级时间有效 |
| 持仓池 | 代码、名称、建仓价、持仓股数 | 无上限 | 止损触发 | 代码唯一 |

### 1.3 决策日志规范

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|:-----|:-----|:----:|:-------|:-----|
| code | string | ✅ | - | 6位数字代码 |
| name | string | ✅ | - | 股票名称 |
| date | string | ✅ | - | YYYY-MM-DD |
| drive_type | string | ✅ | AI审查 | 区分AI审查/实盘建仓/实盘卖出 |
| recommendation | string | ✅ | - | 推荐操作 |
| actual_pnl | float | ❌ | None | 实盘盈亏，非交易记录为None |
| confidence | string | ❌ | 中 | 信心度兜底 |

## 二、常态化校验方案

### 2.1 每日定时校验

| 时间 | 校验项 | 脚本 | 输出 |
|:----|:-------|:-----|:-----|
| 09:00 | 五维数据质量扫描 | `dq_scanner.py --alert` | 告警/正常 |
| 10:00 | LLM格式漂移检测 | `llm_drift_detector.py --alert` | 告警/正常 |
| 10:30 | 盘中复盘（含流水线校验） | `main.py 天枢 full` | 五池状态+报告 |
| 14:30 | 临盘决策（含流水线校验） | `main.py 天枢 full` | 决策方案+报告 |
| 16:00 | 收盘后全量扫描+修复 | `dq_scanner.sh` | 修复日志+日报 |

### 2.2 数据质量告警规则

| 告警ID | 触发条件 | 级别 | 响应 |
|:------:|:---------|:----:|:-----|
| DQ-AL-01 | 腾讯行情字段校验失败(名称/价格) | 🔴 P0 | 停止行情消费，切换备用源 |
| DQ-AL-02 | 多源价格差异>1% | 🟡 P1 | 记录日志，使用腾讯行情 |
| DQ-AL-03 | 复权类型标识缺失 | 🟢 P3 | 自动补充默认值 |
| DQ-AL-04 | 池数据过期(>24h未更新) | 🟡 P1 | 触发行情刷新 |
| DQ-AL-05 | 跨池代码重复 | 🟡 P2 | 自动去重 |
| DQ-AL-06 | K线日期不连续(>5天间隔) | 🟢 P3 | 记录日志 |
| DQ-AL-07 | 评分=0且入池>3天 | 🔴 P0 | 强制降级边缘池 |
| DQ-AL-08 | ST标的自动检测 | 🟡 P1 | 更新ST_STOCKS集合 |

### 2.3 数据修复流程

```
检测到异常 → 判断自愈可行性
  ├─ 可自愈(低风险/可逆) → 自动修复 → 写入修复日志 → 校验通过 → 完成
  ├─ 半自动(中风险) → 告警 → 建议人工确认 → 修复 → 校验
  └─ 不可自愈(高风险) → 立即告警 → 人工介入 → 修复 → 校验
```
