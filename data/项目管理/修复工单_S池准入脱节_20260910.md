## ④ 评分提取：重要设计决策

**放弃"审查汇总表行回退"方案**（工单初稿曾列为方案），原因——验证时发现该方案有
严重的跨标的污染：

```
9-10真实报告结构：
| 代码 | 名称 | 综合评分 | 流转方向 |   ← 审查汇总表（中国石化42）
...
| 代码 | 名称 | 现价 | ... |           ← 重点观察池状态表
| 600141 | 兴发集团 | 31.50 | ... |      ← 无评分列
| 002436 | 兴森科技 | 39.45 | ... |
| 002312 | 川发龙蟒 | 9.55  | ... |

### 兴发集团（600141）
- 参考报告评分仅42分 ...
```

旧全局正则 `评分\s*[：:\s]*(\d+)` 会先匹配到**表格列名"综合评分"**，然后抓到相邻行的
数值 → **"兴发集团的综合评分"实际取到川发龙蟒的 39.45 元现价**。

最终方案：**段内锚定**——以「标名（代码）」为锚点定位标的段落（边界=下一个标名行/
分隔线/文末），仅在段内取分。段内无评分或无锚点 → 返回 `None`。**宁可 None，不可跨标的取分。**

真实数据验证：兴发集团 → 42（命中自身段内"评分仅42分"）；兴森科技 → None；
川发龙蟒 → None。

## 复盘要点

1. **语义歧义**：S池注释写"决策已审查通过、S池只做记录"，但实际来源是重点观察池，
   而重点观察池里住着被 Skeptic 拦下的标的 —— "记事本"定位与"晋级"行为矛盾。
2. **双通道不对称**：决策层消费结构化裁决（JSON），S池写入层消费自由文本正则。
   同一标的在结构化通道被否决、在文本通道被放行，是脱节的结构性根源。
3. **兜底反噬（最重要教训）**：07-21 加兜底的初衷是防格式漂移丢单，但
   `any(k in window)` 纯子串匹配把"不操作"读成"操作"、"买入"读成"买入逻辑矛盾"，
   兜底成了绕过 Gate 的后门。**兜底逻辑必须有否定语境守卫，否则兜底会绕过上层所有闸门。**
4. **自洽信号被丢弃**：决策报告尾部明写"S级操作池: 0只今日主推"，S池却写入3只。
   LLM 与池状态的一致性应作为最后闸门硬校验。
5. **回退方案的隐蔽代价**：任何"正则回退/兜底"方案都要验证**是否会跨越语义边界**取到
   相邻实体的数据。本工单中表格列名 + 相邻行数值即典型，且污染的是**价格**而非评分，
   危害比取错评分更大。
6. **字段名漂移是静默杀手**：`综合分` vs `综合评分` 两套字段并存，单字段读取不报错，
   只静默落到默认值。历史上所有S池过期标的都被当作幻影80分回流，从未被察觉。
   教训：**跨模块字段传递必须有别名兼容 + 单元测试锁定**。
