## 三、运维指南

### 3.1 日常监控

```bash
# 每日开盘前运行数据质量扫描
python3 scripts/dq_scanner.py --verbose

# 告警模式（供Cron捕获）
python3 scripts/dq_scanner.py --alert

# 自动修复模式
python3 scripts/dq_scanner.py --fix
```

### 3.2 行情自愈

```bash
# 修复所有池缺失行情
python3 scripts/quote_healer.py

# 预览模式（不修改）
python3 scripts/quote_healer.py --dry-run

# 指定池修复
python3 scripts/quote_healer.py --pool 快筛候选池
```

### 3.3 LLM格式漂移监控

```bash
# 检测最近3天的LLM输出格式
python3 scripts/llm_drift_detector.py --verbose

# 检测最近7天，告警输出
python3 scripts/llm_drift_detector.py --days 7 --alert
```

### 3.4 数据质量日报

dq_scanner.py 每次运行输出结果保存到 `data/dq/dq_result_YYYY-MM-DD.json`，供日报生成。

## 四、数据质量应急预案

### 4.1 告警响应流程

| 级别 | 触发条件 | 响应动作 | 响应人 | 时限 |
|:----:|:---------|:---------|:------|:----:|
| 🔴 P0 | 核心交易数据损坏/缺失 | 立即停止交易流程，排查数据源，手动修复 | 系统管理员 | 立即 |
| 🟡 P1 | 评分大面积缺失/行情大面积过期 | 运行行情自愈脚本，检查数据源连通性 | 系统管理员 | 15min |
| 🟢 P2 | 单条数据异常/跨池不一致 | 运行dq_scanner --fix，检查修复结果 | 运维人员 | 1h |
| 🔵 P3 | 报告缺失/配置漂移 | 记录日志，下次运行时自动修复 | 自动 | 下次运行 |

### 4.2 常见故障恢复

| 故障场景 | 恢复步骤 |
|:---------|:---------|
| 行情API超时 | ① 检查网络连通性 → ② 运行 `quote_healer.py` 多源轮询 → ③ 检查修复结果 |
| 评分提取失败 | ① 运行 `llm_drift_detector.py` 检查格式漂移 → ② 更新正则模式 → ③ 重新运行审查 |
| 池数据损坏 | ① 检查 `__backups__` 目录备份 → ② 恢复最近可用备份 → ③ 运行 `dq_scanner.py --fix` |
| 决策报告缺失 | ① 检查LLM输出是否正常 → ② 运行 `python main.py decision` 重跑 → ③ 检查报告文件 |

### 4.3 留痕追溯

所有修复操作记录在 `data/dq/dq_fix_log.jsonl`，格式：
```json
{"time": "2026-07-30 10:00:00", "type": "行情自愈", "target": "快筛候选池/300502 新易盛", "before": "价格缺失", "after": "修复价=371.13元", "validated": true}
```
