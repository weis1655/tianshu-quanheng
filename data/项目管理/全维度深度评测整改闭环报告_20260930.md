### 1.3 全链路运行流程

```
数据输入 → 策略计算(快筛→审查→质疑) → 信号生成(决策+兜底+Skeptic+合规)
  → 订单执行(无实盘接口,风控空转) → 绩效复盘(持仓池空转,闭环断裂)
```

### 1.4 链路缺口

- 推荐→建仓→持仓池：无自动化衔接（PoolManager.add_to_holding 零调用；DecisionAgent 只读持仓池；整个交易闭环断在推荐输出后）
- 决策→订单：full_cycle 不产生任何实际订单；条件单引擎存在但触发结果仅 print，无人确认/执行
- 事前合规拦截失效：compliance_manager.check_all 只在推荐记录落库时调用，违规推荐已输出给用户；且参数硬编码 total_capital=1M/bid_price=10 与真实组合脱节
- 组合级风控形同虚设：portfolio_manager.check_portfolio_risk 唯一调用点传入 {s.name: []} 空 positions，跨策略暴露检查永远不触发
- A 股交易制度缺失三项关键校验：停牌检测、集合竞价时段识别、北向资金接入（trigger.py 北向函数为空实现）
- T+1 判重完全依赖持仓池数据，而持仓池无自动入池路径→T+1 判重在真实生产链路中恒为空转
- 涨停/跌停过滤仅在 9:30-15:00 交易时段启用；full_cycle 常规 07:10 启动和盘外 cron 触发时该过滤器完全禁用
- 两套硬规则并存：Orchestrator.check_hard_rules 定义但生产零调用；DecisionAgent._apply_hard_rules 重新实现同类规则但字段解析不同
- ReviewAgent._apply_pool_updates 绕过 PoolManager/GateController 集中管理，池写入规则校验（容量/跨池）在审查阶段不生效
- SkepticAgent LLM 解析失败降级为 pass + degraded=True，标的未经真实质疑审查即进入决策候选
- 弱市简化审查阈值硬编码（涨幅>15%/PE>80/换手>12%/评分<50/量比>5/20日高位>85%/量放大>3倍），不纳入 thresholds.py 统一管理
- 闭环追踪 T+1 数据采集（main.py:872-903）依赖昨日闭环追踪文件存在；文件缺失时静默跳过，无告警
